# Учёт основных средств и амортизации

Учебный модуль для курсовой работы: карточки основных средств, четыре способа
амортизации, закрытие месяца, отчёты, прогноз и журнал действий. Работает на
SQLite «из коробки» и на SQL Server через SSMS/ODBC.

Консольное приложение на C++17, деньги считаются в копейках (`int64_t`), без
чисел с плавающей точкой.

## Что умеет

- справочник материально ответственных лиц (МОЛ);
- приём объектов: основное средство или малоценка (лимит 100 000,00 руб.);
- четыре способа амортизации: линейный, уменьшаемого остатка, по выработке,
  по сумме чисел лет;
- закрытие месяца с контролем графика: без пропусков и повторных закрытий;
- карточка объекта (учебный аналог ОС-6) с историей начислений;
- ведомость остатков, сводка по фирме, отчёт за месяц, итоги за год;
- прогноз амортизации на горизонт до 600 месяцев — без записи в базу;
- отмена последнего закрытия и повторное закрытие;
- списание объекта с причиной;
- журнал действий (аудит) и триггер на создание карточки;
- вход по логину и паролю, две роли: бухгалтер и смотритель;
- выгрузка ведомости и месячного отчёта в CSV для Excel;
- резервная копия: файл SQLite или `BACKUP DATABASE` для SQL Server;
- учебные демо-данные и автоматические проверки.

## Архитектура и слои

| Файл | Что делает |
| --- | --- |
| `include/osmod/model.h`, `src/model.cpp` | доменные типы: `Asset`, `Charge`, `Period`, `DateYmd`, разбор и проверка дат |
| `include/osmod/money.h`, `src/money.cpp` | деньги в копейках: разбор ввода, формат, деление с округлением вниз |
| `include/osmod/depreciation.h`, `src/depreciation.cpp` | стратегии начисления и общий расчёт месяца |
| `include/osmod/store.h` | интерфейс хранилища (репозиторий) |
| `src/sqlite_store.cpp` | хранилище SQLite (файл базы) |
| `src/sqlserver_store.cpp` | хранилище SQL Server через ODBC |
| `include/osmod/service.h`, `src/service.cpp` | бизнес-сценарии: приём, закрытие, списание, отчёты, прогноз, отмена |
| `include/osmod/report.h`, `src/report.cpp` | выгрузка CSV |
| `src/ui/input.*` | ввод с проверкой: суммы, даты, числа, да/нет |
| `src/ui/reports.*` | печать таблиц и отчётов в консоль |
| `src/ui/menu.*` | меню, вход, учебный сценарий |
| `src/main.cpp` | точка входа и ключи запуска |
| `tests/test_main.cpp` | автотесты без внешних библиотек |

Использованы три простых приёма, без «магии»:

1. **Стратегия** — каждый способ амортизации это отдельный класс
   `DepreciationStrategy`. Единственная точка вариации —
   `strategyFor(Method)` в `src/depreciation.cpp`. Остальной код о способах
   ничего не знает.
2. **Репозиторий** — `Store` описывает, что нужно сервису, а SQLite и SQL Server
   реализуют это по-своему. `Service` не знает, куда пишет.
3. **Сервисный слой** — все правила учёта собраны в `Service`, меню только
   спрашивает данные и печатает ответы. Поэтому правила проверяются тестами без
   консоли.

## Сборка

### Вариант 1: `build.bat` (MinGW-w64)

Нужен `g++` с SQLite и заголовками ODBC. Проверено на MinGW-w64 g++ 14.2
(`C:\msys64\mingw64\bin\g++.exe`).

```bat
build.bat
```

Если `g++` лежит в другом месте, поправьте переменную `GXX` в начале файла.
Сборка статическая, DLL рядом не нужны. Результат:

```
build\osmod.exe
build\osmod_tests.exe
```

### Вариант 2: CMake

```bat
cmake -S . -B build-cmake -G "MinGW Makefiles"
cmake --build build-cmake
```

Цели: `osmod` (приложение) и `osmod_tests` (проверки). Компилятору должны быть
видны `sqlite3` и `odbc32`. Для MSVC в `CMakeLists.txt` уже включён `/utf-8`,
иначе кириллица в строковых литералах ломается.

## Быстрый старт на SQLite

```bat
build.bat
build\osmod.exe --demo
build\osmod.exe
```

- `--demo` создаёт отдельную базу `data\demo.db`, заводит учебную фирму,
  закрывает 13 месяцев и печатает все отчёты. Файл по указанному пути
  **перезаписывается**. Свой путь: `build\osmod.exe --demo build\probe.db`.
- обычный запуск спрашивает файл базы: нажмите Enter — будет
  `data\krovlaya.db`.

На пустой базе приложение предложит завести учебную фирму. Ответьте `да`, затем
войдите как `buh` / `buh123`.

Пути считаются от текущего каталога, поэтому запускайте `osmod.exe` из корня
проекта (или создайте `data` рядом с exe).

## Подключение SQL Server (SSMS)

Нужны SQL Server 2019/2022, SSMS 18+ и драйвер
`ODBC Driver 17 for SQL Server` (или 18). Базу можно подготовить скриптами.

### Порядок скриптов

Выполняйте по одному, каждый начинается с `USE AssetOs`:

| Скрипт | Что делает |
| --- | --- |
| `sql/sqlserver/01_create_db.sql` | создаёт пустую базу `AssetOs`, простая модель восстановления |
| `sql/sqlserver/02_schema.sql` | таблицы, ключи, индексы, ограничения (повторный запуск безопасен) |
| `sql/sqlserver/03_roles_audit.sql` | роли `os_accountant` / `os_reader`, права, триггеры аудита и запрета правки начислений |
| `sql/sqlserver/04_seed.sql` | учебные карточки, МОЛ и учётки `buh` / `chief` |
| `sql/sqlserver/05_backup.sql` | пример `BACKUP DATABASE` (поправьте путь) |
| `sql/sqlserver/06_queries.sql` | готовые выборки для проверки и отчёта |

В SSMS: `File → Open → File`, затем `Execute`. Файлы сохранены в UTF-8 без BOM;
SSMS читает их нормально. Если запускаете через `sqlcmd`, добавьте кодировку
`-f 65001`, иначе кириллица в литералах (`N'триггер'`) испортится:

```bat
sqlcmd -S localhost -E -C -f 65001 -i sql\sqlserver\01_create_db.sql
sqlcmd -S localhost -E -C -f 65001 -i sql\sqlserver\02_schema.sql
sqlcmd -S localhost -E -C -f 65001 -i sql\sqlserver\03_roles_audit.sql
sqlcmd -S localhost -E -C -f 65001 -i sql\sqlserver\04_seed.sql
```

Скрипты не обязательны: если подключиться к существующей пустой базе,
приложение само создаст таблицы (`migrate()`), а учебные данные заведёт пункт
меню 15. Но роли СУБД и триггер запрета правки появляются только из
`03_roles_audit.sql`.

### Строка подключения

При запуске приложение спрашивает файл или строку подключения. Строка SQL Server
начинается с `Driver=`, например:

```
Driver={ODBC Driver 17 for SQL Server};Server=localhost;Database=AssetOs;Trusted_Connection=yes;
```

- именованный экземпляр: `Server=.\SQLEXPRESS`;
- вход SQL-логином: `UID=sa;PWD=пароль` вместо `Trusted_Connection=yes`;
- драйвер 18 по умолчанию шифрует канал, для учебного локального сервера
  добавьте `TrustServerCertificate=yes` (или `Encrypt=no`).

В приложении одна строка подключения, а роль пользователя берётся из таблицы
`users.role_name` и режет меню. Роли СУБД нужны, если в базу заходят ещё и из
SSMS:

```sql
CREATE LOGIN [DOMAIN\student] FROM WINDOWS;
USE AssetOs;
CREATE USER [DOMAIN\student] FOR LOGIN [DOMAIN\student];
ALTER ROLE os_accountant ADD MEMBER [DOMAIN\student];
```

`os_accountant` может читать и заводить карточки/начисления и удалять проводки
месяца (отмена закрытия), но не удаляет карточки. `os_reader` — только чтение.
Отдельную строку начисления менять нельзя: сработает `trg_charge_lock`.

| 5 | отчёт за месяц | год, месяц |
| 6 | итоги за год | год |
| 7 | прогноз амортизации | номер, горизонт, средняя выработка |
| 8 | журнал действий | сколько последних записей |
| 9 | способы начисления | — |
| 10 | принять объект | номер, название, id МОЛ, дата, суммы, срок, способ, место |

| 12 | списать объект | номер, дата, причина, подтверждение |

### Пример: принять объект

```
Команда (0..17): 10
Номер      Наименование ...            (печатается справочник МОЛ)
Инвентарный номер, например ОС-0100: ОС-0100
Наименование: Штукатурная станция PFT G4
id МОЛ (1..1000000000): 2
Дата принятия (ГГГГ-ММ-ДД или ДД.ММ.ГГГГ): 12.05.2025
Первоначальная стоимость, руб.: 385 000
Ликвидационная стоимость, руб.: 25 000
Срок полезного использования, месяцев (1..600): 60
Способы начисления:
  1 — линейный
  2 — уменьшаемого остатка
  3 — пропорционально выработке
  4 — по сумме чисел лет
Номер способа (1..4): 1
Место хранения: склад, секция Б
Примечание: принята по накладной 17
```

Первое начисление по этой карточке — за 06.2025 (месяц, следующий за приёмом).
Если стоимость меньше 100 000,00 руб., карточка автоматически станет
малоценкой: срок, ликвидационная и план обнулятся, амортизация не начисляется.

## Правила учёта

1. **Лимит признания ОС** — `limit_kop` в настройках, по умолчанию 10 000 000
   копеек = 100 000,00 руб. Строго меньше лимита — малоценка; ровно лимит —
   основное средство.
2. **Малоценка** хранится на балансе, но не амортизируется: способ приводится к
   линейному, срок, ликвидационная и план — к нулю.
3. **Первое начисление** — месяц, следующий за месяцем принятия. Принят в мае
   2025 — первая проводка за июнь 2025.
4. **Без пропусков и повторов.** Для каждого объекта месяц закрывается строго
   по порядку. Закрыть 06.2025, пропустив 05.2025, нельзя; закрыть месяц
   дважды тоже.
5. **Последний месяц срока забирает остаток.** Сумма начислений за весь срок
   ровно равна `первоначальная − ликвидационная`. Копейки не теряются.
6. **Ниже ликвидационной не уходим.** Остаток меньше месячной суммы обрезается.
   Уменьшаемый остаток начисляет минимум 1 копейку в месяц, пока есть остаток.
7. **Выработка.** Нельзя списать больше оставшегося плана. Месяц с нулевой
   выработкой даёт проводку на 0 и считается закрытым. Месяц, в котором план
   закрывается, забирает весь оставшийся остаток. Срок службы остаётся рамкой:
   в последний месяц срока остаток закрывается, даже если план не выбран.
8. **Списание.** Для основного средства месяц списания должен быть уже закрыт,
   иначе выбытие выпадет из графика. Списать раньше месяца принятия нельзя.
   Малоценку можно списать в любой момент.
9. **Отмена закрытия** снимает все проводки последнего закрытого месяца одной
   операцией и пишет запись в журнал. После этого месяц можно закрыть заново.
   Отменить «месяц в середине» нельзя.
10. **Аудит.** Приём, закрытие, отмена, списание и учебные данные пишутся в
    `audit_log`. Создание карточки дополнительно отмечает триггер.
11. **Деньги** — целые копейки, все деления округляются вниз, остаток добирается
    последним месяцем. Никаких `double`.
12. **Месяц считается целиком.** Сначала проверяются и рассчитываются все
    объекты, и только потом пишутся проводки: ошибка на одном объекте не
    оставляет месяц закрытым наполовину.

## Способы и формулы

Обозначения: `B = стоимость − ликвидационная` (амортизируемая база),
`T` — срок в месяцах, `R` — уже начислено, `t` — месяцев уже закрыто,
`k` — коэффициент уменьшаемого остатка (хранится целым ×100, 200 = 2,00).

| Способ | Месячная сумма | Особенность |
| --- | --- | --- |
| Линейный | `B / T`, вниз до копейки | последний месяц берёт остаток |
| Уменьшаемого остатка | `(стоимость − R) * k / (T * 100)` | минимум 1 копейка, пока есть остаток |
| По выработке | `B * выработка / план` | последняя единица плана берёт остаток |
| По сумме чисел лет | `B * 2 * (T − t) / (T * (T + 1))` | вес месяца убывает от `T` до 1 |

Пример линейного способа: 100,00 руб. за 3 месяца → 33,33 + 33,33 + 33,34.
Пример уменьшаемого остатка из демо: Газель, 1 640 000,00 − 240 000,00 =
1 400 000,00 руб., срок 60, коэффициент 2,00 → первый месяц 54 666,66 руб.

Порядок расчёта месяца: база и остаток → стратегия → ограничение остатком →
запись `amount_kop` и `book_kop`. Последний месяц срока и закрытие плана
выработки обрабатываются в `chargeDepreciation()` до вызова стратегии.

## Форматы ввода

- **Суммы:** `186400`, `186 400`, `186400,50`, `186400.50`, `1 864,5`,
  `1.640.000 руб.`, `5000 ₽`. Пробелы (включая неразрывный), точки как
  разделители тысяч и суффиксы `руб.`/`₽` понимаются. Дробная часть — 1–2
  цифры, это копейки. Отрицательные суммы в меню не принимаются.
- **Даты:** `2025-05-12` или `12.05.2025`. Календарь проверяется: 29.02.2023 и
  31.04.2025 не пройдут.
- **Коэффициент:** целое ×100, от 100 до 300 (1,00–3,00).
- **План выработки:** целое больше нуля.
- **Да/нет:** `да`, `д`, `y`, `yes` или `нет`, `н`, `n`, `no` в любом регистре.
- **Путь:** пустая строка означает значение по умолчанию, если оно предложено.

При ошибке ввода приложение объясняет причину и спрашивает снова, а не
завершается.

## Отчёты и CSV

Ведомость CSV: `Номер;Наименование;Способ;Первоначальная;Начислено;Балансовая;МОЛ;Состояние`.

Отчёт за месяц CSV: `Месяц;Номер;Наименование;МОЛ;Начислено;Балансовая;Выработка`.

Файл пишется в UTF-8 с BOM, разделитель `;`, десятичная запятая, переводы строк
CRLF. В Excel: `Данные → Из текста/CSV`, кодировка UTF-8, разделитель «точка с
запятой». Суммы в CSV — без пробелов между разрядами, чтобы Excel видел число.

Прогноз ничего не пишет в базу и не попадает в журнал: это только чтение.
Для способа по выработке, если средняя выработка не задана, берётся
`план / срок` (минимум 1 единица в месяц).

## Тесты

```bat
build\osmod_tests.exe
```

Ожидаемый вывод: `все проверки сошлись`. Всего 87 проверок:

- SHA-256 (включая хеши учебных паролей из SQL-скриптов) и разбор сумм;
- календарные даты, високосные годы, мусор после даты;
- линейный способ, хвост копеек 33+33+34, пример 7 500,00;
- уменьшаемый остаток 54 666,66 и упор в ликвидационную;
- выработка 6 400,00 и закрытие плана остатком;
- сумма чисел лет: первый месяц 1 967,21 и точное закрытие базы;
- отказы: ликвидационная выше стоимости, девятый способ, выработка без плана,
  выработка больше плана, повторный инвентарный номер;
- демо-сценарий: 13 закрытий, итоги, отчёты за год и месяц, прогноз без записи,
  CSV с BOM и `;`, отмена и повторное закрытие;
- малоценка, списание, запрет списания в незакрытом месяце и раньше принятия,
  пропуск списанного объекта, отсутствие полузакрытого месяца при ошибке.

Тесты создают временные базы `data/test-*.db` и удаляют их за собой.

## Схема базы

| Таблица | Назначение | Ключевые поля |
| --- | --- | --- |
| `persons` | МОЛ | `full_name`, `job_title` |
| `users` | вход в приложение | `login`, `pass_hash` (SHA-256), `role_name` |
| `assets` | карточки | `inv_no`, `person_id`, `kind`, `status`, `method`, `accepted_on`, `cost_kop`, `liq_kop`, `life_months`, `decline_x100`, `plan_units`, `place`, `note`, `retired_on` |
| `charges` | начисления | `asset_id`, `y`, `m`, `amount_kop`, `book_kop`, `units`, уникальность `(asset_id, y, m)` |
| `audit_log` | журнал | `ts`, `user_name`, `action`, `details` |
| `settings` | настройки | `company`, `limit_kop`, `start_rule` |

Коды: `kind` 1 — ОС, 2 — малоценка; `status` 1 — в учёте, 2 — списано;
`method` 1 — линейный, 2 — уменьшаемого остатка, 3 — по выработке,
4 — по сумме чисел лет.

Ограничения: `CHECK (method BETWEEN 1 AND 4)`, `CHECK (m BETWEEN 1 AND 12)`,
неотрицательные суммы, внешние ключи, уникальность инвентарного номера и месяца
начисления. Индексы по `asset_id` и `person_id`.

SQL-скрипты для SQLite (не обязательны, приложение создаёт всё само):

```bat
sqlite3 data\manual.db < sql\sqlite\01_schema.sql
sqlite3 data\manual.db < sql\sqlite\02_seed.sql
sqlite3 data\manual.db < sql\sqlite\03_queries.sql
```

Затем в приложении укажите `data\manual.db` и войдите как `buh` / `buh123`.

## Роли и пароли

- `buh` / `buh123` — бухгалтер: все пункты меню.
- `chief` / `view123` — смотритель: пункты 1–9, 16, 17; запись закрыта.

Пароли хранятся как SHA-256 без соли. Это учебный проект, для настоящей системы
так делать нельзя. Новый пользователь добавляется SQL-запросом; хеш удобно
посчитать в PowerShell:

```powershell
$b=[Text.Encoding]::UTF8.GetBytes('новый пароль')
([BitConverter]::ToString([Security.Cryptography.SHA256]::Create().ComputeHash($b))).Replace('-','').ToLower()
```

Полученную строку вставьте в `users.pass_hash` с ролью `бухгалтер` или
`смотритель`.

## Резервное копирование

Пункт меню 14.

- SQLite: копия через `sqlite3_backup` — получается согласованный файл, даже
  если база открыта.
- SQL Server: `BACKUP DATABASE ... WITH COPY_ONLY`. Путь видит **сервер**, а не
  ваш рабочий стол; у службы SQL Server должны быть права на каталог. Готовый
  пример — `sql/sqlserver/05_backup.sql`.

## Как добавить пятый способ амортизации

Это и есть обещанная точка вариации. Порядок:

1. `include/osmod/model.h` — добавьте код в `enum class Method`, например
   `NewMethod = 5`.
2. `src/depreciation.cpp` — новый класс-наследник `DepreciationStrategy`
   (имя и `monthlyAmount`), добавьте `static` экземпляр и ветку в
   `strategyFor()`.
3. `include/osmod/depreciation.h` — увеличьте `kMethodCount` до 5.
4. Ограничения в SQL: `sql/sqlite/01_schema.sql`,
   `sql/sqlserver/02_schema.sql` и `CHECK` в `migrate()` обоих хранилищ —
   `BETWEEN 1 AND 5`.
5. Если способу нужен свой параметр, добавьте поле в `Asset`, колонку в схему и
   вопрос в `acceptFlow()` (как сделано для коэффициента и плана выработки).
6. Добавьте проверку в `tests/test_main.cpp`.

Меню способов, карточка и ведомость подхватят новое название сами: они берут его
из `strategyFor(...).name()`, а длина меню — из `kMethodCount`.

Новое хранилище (например, PostgreSQL) — это ещё один класс с интерфейсом
`Store` и своя функция `open...()`.

## Разбор частых ошибок

| Сообщение / симптом | Причина и что делать |
| --- | --- |
| `Не нашёл g++ по пути ...` | поправьте `GXX` в `build.bat` |
| `sqlite3.h: No such file` | в MinGW нет SQLite; установите пакет или укажите include/lib |
| `SQL Server не пустил` | не создана база `AssetOs`, не тот экземпляр, нет драйвера ODBC или не разрешён TCP |
| `[IM002] Data source name not found` | нет драйвера с таким именем; проверьте список в `odbcad32.exe` (64-бит) и имя `Driver={...}` |
| ошибка шифрования у драйвера 18 | добавьте `TrustServerCertificate=yes` |
| `Не пустил. Осталось попыток` | неверный логин/пароль или пустая таблица `users`; заведите демо-данные |
| `первое начисление должно быть за ...` | закрывайте месяцы по порядку, начиная со следующего после приёма |
| `жду месяц ..., а пришёл ...` | пропуск в графике; закройте пропущенный месяц |
| `месяц ... уже закрыт` | используйте пункт 13 (отмена закрытия), потом закройте заново |
| `сначала закройте амортизацию за ...` | перед списанием закройте месяц выбытия |
| `Роль «смотритель» только смотрит` | войдите как `buh` |
| Кириллица ромбиками в консоли | запускайте в Windows Terminal; приложение само ставит кодовую страницу UTF-8 |
| Кириллица испорчена в базе после `sqlcmd` | запускайте скрипты с `-f 65001` или через SSMS |
| CSV открылся одной колонкой | в Excel выберите разделитель «точка с запятой», кодировку UTF-8 |
| `--demo` стёр базу | так и задумано для указанного файла; по умолчанию теперь `data/demo.db` |

## Ограничения учебного проекта

Однопользовательская работа, нет блокировок и транзакций между параллельными
сеансами; нет НДС, налогового учёта, переоценки и модернизации; карточку нельзя
отредактировать — только списать и завести заново; пароли без соли. Этого
достаточно для курсовой, но недостаточно для промышленной эксплуатации.
